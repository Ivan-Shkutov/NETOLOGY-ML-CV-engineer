## Описание задачи

Дан набор CSV-файлов с синтетическими данными о заказах интернет-магазина.
Требуется разработать скрипт, который:

1. Находит **все** CSV-файлы в папке `data/` и обрабатывает их по очереди
   (пакетная обработка).
2. Для каждого файла фильтрует только заказы со статусом `Delivered`.
3. Рассчитывает три метрики по каждому файлу:
   - **общая выручка** — сумма значений колонки `total_amount`;
   - **средний чек** — среднее значение `total_amount`;
   - **количество заказов** — число отфильтрованных строк.
4. Сохраняет сводку по всем файлам в один CSV-отчёт в папке `reports/`.
5. Не падает при повреждённых, пустых или неверно отформатированных
   файлах: пропускает такой файл, пишет ошибку в лог и продолжает работу.
6. Выводит в консоль количество успешно обработанных файлов и количество
   файлов с ошибками.

Вся логика работы с данными упакована в класс `OrderAnalyzer`.

## Что делает программа

Скрипт выполняет следующий конвейер:

```
┌──────────────────┐
│  data/*.csv      │  ← все CSV в папке
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│   load_file()    │  ← чтение + проверка структуры
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│ filter_delivered │  ← оставляем только Delivered
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│calculate_metrics │  ← сумма, среднее, количество
└────────┬─────────┘
         │
         ▼
┌──────────────────┐
│summary_report.csv│  ← итоговый отчёт
└──────────────────┘

Параллельно: при ошибке → logs/errors.log
```

## Подготовка данных

### Основные файлы

Положи в папку `data/` CSV-файлы с заказами. Источник данных —
[Synthetic Order Records](https://www.kaggle.com/datasets/swainproject/synthetic-order-records-10k-to-10m-records)
на Kaggle (лицензия CC BY 4.0). Для проверки достаточно двух файлов:

- `order_10000.csv`
- `order_100000.csv`

### Тестовый «испорченный» файл

Для проверки устойчивости скрипта создай файл `data/broken.csv` с
нечисловыми значениями в `total_amount`:

```csv
order_id,person_id,order_date,status,total_amount,currency,payment_method,shipping_method,notes
1,1,2021-03-15,Delivered,abc,USD,credit_card,standard,
2,2,2021-03-16,Delivered,не_число,EUR,paypal,express,
```

Этот файл должен быть **пропущен** и занесён в лог — а не уронить скрипт.

### Структура входных данных

Каждый CSV содержит следующие колонки:

| Поле | Описание | Тип | Пример |
|---|---|---|---|
| `order_id` | Уникальный номер заказа | Целое | 1, 2, 2003 |
| `person_id` | ID покупателя | Целое | 1, 100, 5000 |
| `order_date` | Дата создания заказа | Строка (YYYY-MM-DD) | 2021-03-15 |
| `status` | Текущий статус заказа | Строка | Pending, Shipped, Delivered, ... |
| `total_amount` | Общая сумма заказа | Число с плавающей точкой | 24.99, 599.95 |
| `currency` | Код валюты | Строка | USD, EUR, GBP |
| `payment_method` | Способ оплаты | Строка | credit_card, paypal, klarna |
| `shipping_method` | Способ доставки | Строка | standard, express, fedex |
| `notes` | Примечания | Строка | ~5% записей заполнено |

## Запуск

Из корня проекта:

```bash
python run.py
```

Скрипт:
1. Создаст папки `reports/` и `logs/`, если их нет.
2. Обойдёт все `.csv` в `data/`.
3. Для каждого файла посчитает метрики.
4. Сохранит отчёт в `reports/summary_report.csv`.
5. Выведет итоговую статистику в консоль.

## Как устроен код

### `config.py`

Все настройки собраны в одном месте — это упрощает поддержку и
соответствует принципу «отделения логики от конфигурации».

```python
BASE_DIR = Path(__file__).resolve().parent
DATA_DIR = BASE_DIR / "data"
REPORTS_DIR = BASE_DIR / "reports"
LOGS_DIR = BASE_DIR / "logs"
REPORT_FILENAME = "summary_report.csv"
LOG_FILENAME = "errors.log"
STATUS_COLUMN = "status"
AMOUNT_COLUMN = "total_amount"
DELIVERED_STATUS = "Delivered"
REQUIRED_COLUMNS = [...]
```

Если нужно изменить поведение скрипта — правится **только этот файл**.

### `src/analyzer.py` — класс `OrderAnalyzer`

Вся логика инкапсулирована в одном классе. Методы:

| Метод | Что делает |
|---|---|
| `__init__` | Принимает настройки, сохраняет как атрибуты, создаёт папки, настраивает логгер |
| `_setup_logger` | Настраивает запись ошибок в `logs/errors.log` |
| `_log_error` | Пишет сообщение в лог и увеличивает счётчик ошибок |
| `load_file` | Читает CSV, проверяет существование, не пустой ли, все ли колонки на месте, числовой ли `total_amount` |
| `filter_delivered` | Оставляет строки, где `status == "Delivered"` |
| `calculate_metrics` | Считает сумму, среднее и количество |
| `process_file` | Обрабатывает **один** файл; при ошибке → лог, возврат `None` |
| `process_all_files` | Обходит **все** CSV, собирает результаты, сохраняет отчёт |
| `get_summary` | Возвращает статистику: сколько обработано, сколько с ошибками |

### `run.py`

Тонкая точка входа:

```python
def main():
    analyzer = OrderAnalyzer(...)
    report_df = analyzer.process_all_files()
    summary = analyzer.get_summary()
    # печать результата

if __name__ == "__main__":
    main()
```

В `main()` **нет бизнес-логики** — только создание объекта и вызовы
методов.

## Устойчивость к ошибкам

Скрипт **не падает** при следующих ситуациях:

- файл не существует;
- путь ведёт к директории, а не к файлу;
- файл пустой;
- в файле отсутствуют обязательные колонки;
- в колонке `total_amount` лежат нечисловые значения;
- ошибки чтения CSV (кодировка, разделитель и т.п.).

Во всех случаях ошибка:

1. **Логируется** в `logs/errors.log`.
2. **Увеличивает счётчик** `error_count`.
3. **Не останавливает** обработку остальных файлов.

Это реализовано через `try/except` в методе `process_file()`:

```python
try:
    df = self.load_file(file_path)
    delivered = self.filter_delivered(df)
    metrics = self.calculate_metrics(delivered)
except Exception as exc:
    self._log_error(file_path.name, str(exc))
    return None
```

## Используемые технологии

- **Python 3.8+** — язык программирования.
- **pandas** — чтение CSV и работа с табличными данными.
- **pathlib** — кроссплатформенная работа с путями файловой системы.
- **logging** — стандартная библиотека для ведения логов.

Архитектурные принципы, использованные в проекте:

- **Инкапсуляция** — вся работа с данными внутри класса.
- **Разделение ответственности** — конфиг, логика, точка входа в разных файлах.
- **DRY** — нет дублирования кода.
- **Отказоустойчивость** — обработка ошибок без остановки скрипта.

## Возможные проблемы и решения

### `ModuleNotFoundError: No module named 'pandas'`

Установи библиотеку:

```bash
pip install pandas
```

или

```bash
python -m pip install pandas
```

### `ModuleNotFoundError: No module named 'src'`

Запускай `run.py` **из корня проекта**, а не из другой папки:

```bash
cd "Итоговая проектная работа."
python run.py
```

### `FileNotFoundError` при запуске

Проверь, что файлы лежат в `data/`:

```bash
dir data
```

Должны быть `order_10000.csv`, `order_100000.csv` и `broken.csv`.

### Кракозябры в CSV или логе

Файл сохранён не в UTF-8. При сохранении `.py`-файлов в редакторе
выбирай кодировку **UTF-8**. В Excel открой CSV через
**Данные → Из текста** и укажи UTF-8.

### В отчёте слишком мало/много строк

Проверь, что в `data/` только нужные CSV. Не заливай в папку
гигабайтные файлы — программа будет их обрабатывать очень долго.
